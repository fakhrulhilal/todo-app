# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

One todo app implemented several times in Rust, in a single Cargo workspace. All implementations share a **contract** so they are interchangeable: any frontend works with any backend, and all apps can share one database at the same time. `README.md` is the detailed spec (config keys, error format, health checks, schema workflow, compose); read the relevant section before changing behaviour that crosses implementations.

| Folder               | Package                | Notes |
|----------------------|------------------------|-------|
| `contract/`          | `todo-contract`        | Shared model + validation (`openapi` feature adds utoipa derives); also holds `openapi.json` |
| `backend/axum/`      | `todo-backend`         | Reference backend; its tests write `contract/openapi.json` |
| `backend/ntex/`      | `todo-backend-ntex`    | Same API on compio runtime, no tokio at all (sqlx uses `runtime-smol`) |
| `backend/salvo/`     | `todo-backend-salvo`   | Same API on Salvo/tokio; OpenAPI still from utoipa, not salvo-oapi |
| `backend/actix/`     | `todo-backend-actix`   | Same API on actix-web 4 (tokio, one runtime per worker); extractor errors via `JsonConfig`/`PathConfig`/`QueryConfig` error handlers |
| `frontend/dioxus/`   | `todo-frontend`        | WASM client, built with `dx` |
| `frontend/leptos/`   | `todo-frontend-leptos` | WASM client, built with Trunk; Tailwind + Rust/UI (see its README) |
| `frontend/sycamore/` | `todo-frontend-sycamore` | WASM client, built with Trunk; Sycamore 0.9 + sycamore-router, plain CSS (see its README) |
| `fullstack/topcoat/` | `todo-fullstack`       | Server-rendered, no JSON API (see its README and `docs/web-ui.md`) |

## Commands

Run everything from the repository root (except Trunk and Playwright).

```sh
cargo test                                   # contract, all backends, topcoat (default-members; frontends excluded)
cargo test -p todo-backend                   # one package
cargo test -p todo-backend --test api todos  # one test module / name filter (backend tests live in tests/api/)
cargo run -p todo-backend                    # http://127.0.0.1:8080
cargo run -p todo-backend-ntex -- -p 8090
cargo run -p todo-backend-salvo -- -p 8091
cargo run -p todo-backend-actix -- -p 8092
dx serve -p todo-frontend --port 8081        # needs dioxus-cli matching the dioxus crate (0.7.10)
(cd frontend/leptos && trunk serve)          # :8082; needs trunk 0.21.x
(cd frontend/sycamore && trunk serve)        # :8086
topcoat asset bundle --package todo-fullstack && cargo run -p todo-fullstack   # binary refuses to start without bundled assets; tests don't need them
docker compose up -d --build                 # whole stack on PostgreSQL
./bench.sh all | ./bench.sh <name>           # oha load test; update benchmark.md after changing an implementation
```

Frontends only build for `wasm32-unknown-unknown`; plain `cargo build` skips them. Clients read `TODO_API_URL` at **compile time** (unset → `http://127.0.0.1:8080`, empty → same origin).

All backends default to `sqlite://data/todo.db` relative to the CWD, so run one at a time locally or pass a different `--database-url`.

### UI tests (Playwright, in `tests/`)

Run against the compose stack, not against `cargo run`:

```sh
docker compose up -d --wait
cd tests && npm install && npx playwright install chromium
npm test                       # every client, serially (shared DB)
npm run test:leptos            # or test:dioxus / test:sycamore / test:topcoat
```

Locate elements by role/label, never CSS class (clients are styled differently). Each test creates and cleans up its own todos. A UI test exercises whichever backend is *active* in compose — before a full frontend test, switch the `api`/`backend` network aliases and the `api.todo.local` OrbStack label to the backend under test and verify it (README: "Switch the backend behind the clients").

## Architecture and cross-cutting rules

**Every backend has the same layout** (`src/{api,cli,config,domain,logging,store}.rs`, `api/{health,problem,todos}.rs`, `store/{postgres,turso}.rs`, `config/default.yaml`, `tests/api/<one module per src file>.rs`). When changing one backend's behaviour, the other backends (and often topcoat) need the same change. Required of every backend:

- **OpenAPI is the contract.** `GET /api/openapi.json` is generated by utoipa. The axum test `openapi_document_is_written_to_the_contract` rewrites `contract/openapi.json`; ntex/salvo/actix tests assert they serve exactly that file. So after an API change: run `cargo test -p todo-backend` first, commit the updated `contract/openapi.json`, then make the other backends match.
- **Every error is RFC 9457 `application/problem+json`**, including framework-raised ones (404, 405, malformed body, bad path/query). Validation failures are 422 with an `errors` map. Salvo needs custom extractors (`api/extract.rs`) and catchers to match axum's statuses — axum's behaviour is the reference.
- **Config** merges `config/default.yaml` → `config.yaml`/`--config` → env (`SECTION__KEY`) → CLI (`--section-key`), figment-style; one key name across all three.
- **Logging:** text when `env=local`, JSON when `production` (`log.format=auto`).
- **Health:** `/health/live` and `/health/ready` return `Healthy|Degraded|Unhealthy` as plain text, `?format=json` for detail; checks registered in `src/api.rs`.
- **Storage** is a `TodoStore` trait chosen by URL scheme in `store::connect`: `sqlite:` → embedded Turso, `postgres://` → sqlx. Backend tests spin up the real app on a random port with `sqlite::memory:`.
- `domain.rs` re-exports `todo_contract::*` and adds server-only helpers (UUIDv7 ids, microsecond timestamps).

**Schema changes go in three places** so every path ends at the same schema:
1. `db/postgres/schema.sql` (declarative, applied by pgschema in compose with `database.migration=false`)
2. `db/postgres/migrations/000N_<name>.sql` (picked up by `sqlx::migrate!`)
3. `db/sqlite/000N_<name>.sql` — **and** add it to the `MIGRATIONS` array in every `store/turso.rs` (axum, ntex, salvo, actix, topcoat); SQLite migrations are listed by hand via `include_str!`.

Never edit an already-applied migration (sqlx checksum check). pgschema drops anything in `public` not in `schema.sql` except what `.pgschemaignore` lists, and does not backfill data.

**Adding an implementation:** put it at `backend/<framework>/` (or `fullstack/`, `frontend/`), add it to workspace `members` (and `default-members` if it builds natively), use the contract crate and `db/` schema, satisfy the required backend behaviours, give it a `Dockerfile` (FROM scratch + tiny-hc healthcheck) and a `backend-<framework>` service in `compose.yaml` — `bench.sh` relies on that service name.

## Build details worth knowing

- Release profile uses thin LTO; the Leptos release build uses the `wasm-release` profile (size-optimized), selected in `frontend/leptos/index.html`.
- Images are multi-arch (amd64 + arm64) cross-compiled; axum via `docker buildx bake` (`docker-bake.hcl`), others via `docker buildx build -f backend/<name>/Dockerfile .` (context is the repo root).
- CI: `.github/workflows/image.yml` runs `cargo test --locked` and publishes the axum image; `pages.yml` deploys the Dioxus client to GitHub Pages.
- `frontend/leptos/src/components/ui/` are vendored Rust/UI files kept unchanged from upstream apart from header and `cargo fmt`; don't refactor them.
